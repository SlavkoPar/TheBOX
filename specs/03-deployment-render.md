# 03 — Deployment to Render (Blueprint)

## Goal

Deploy TheBOX to Render.com from `render.yaml` at the repo root.

## What the Blueprint creates

| Resource | Name | Notes |
| --- | --- | --- |
| Postgres database | `thebox-db` | free plan, region `frankfurt` |
| Web service | `thebox` | Docker, free plan, region `frankfurt`, health check `/api/health` |

## Design

- **One web service, one origin.** The `Dockerfile` builds the frontend (Node stage) and copies `frontend/dist` into the Python image. Flask serves it when `FRONTEND_DIST` is set: real files are returned as-is, any other non-`/api` path returns `index.html` so client-side routes such as `/confirm` work.
- **Why not a separate static site:** the session cookie is `SameSite=Lax`, and two `*.onrender.com` subdomains count as different sites, so the cookie would not be sent to a separately hosted API.
- **Server:** gunicorn, 2 workers, bound to `$PORT`.
- **Migrations:** `flask db upgrade` runs at container start, before gunicorn. (`preDeployCommand` is not available on Render's free plan.)
- **Database URL:** Render supplies `postgresql://...`; `app/config.py` rewrites it to `postgresql+psycopg://...`.
- **Confirmation links:** `FRONTEND_URL` falls back to `RENDER_EXTERNAL_URL`, which Render sets to the service's public URL. Set `FRONTEND_URL` explicitly when using a custom domain.

## Environment variables

| Variable | Source |
| --- | --- |
| `DATABASE_URL` | from `thebox-db` connection string |
| `SECRET_KEY` | generated by Render |
| `SESSION_COOKIE_SECURE` | `1` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `MAIL_FROM` | entered when the Blueprint is created (`sync: false`) |

## Deploying

1. Push the repository to GitHub or GitLab.
2. In Render: **New → Blueprint**, pick the repository, fill in the SMTP values, apply.
3. Later pushes to the branch deploy automatically.

## Not included

- Custom domain
- Background worker for sending email
- Paid-plan features: pre-deploy migrations, zero-downtime deploys, database backups
